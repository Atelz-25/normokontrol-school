# Этап 7: PDF, шаблон, план «по одному», история, памятка, отзыв

## Что сделано

1. **Проверка PDF.** Страницы и текст с координатами читает библиотека pdf.js, проверка — в `src/core/pdf/analyze.ts`: формат A4, число страниц, встроены ли шрифты, гарнитуры, размер шрифта, а по краю текста — поля, номера страниц и начало частей.
2. **Шаблон .docx** по выбранным требованиям (`src/core/template/build.ts`).
3. **Фильтр плана** («Только ошибки», «Исправлю сам») и **режим «По одному»**.
4. **История попыток:** «Попытки: 61 → 73 → 92» под вердиктом.
5. **Памятка требований** на экране «Требования», её можно распечатать.
6. **Отзыв ученику** в режиме учителя одной кнопкой.

## Почему так

- **PDF — это не документ, а картинка из букв.** В нём нет абзацев и стилей, только «буква такая-то стоит в точке (x, y)». Поэтому по PDF нельзя честно проверить красную строку или пустые строки, а поля измеряются по краю текста — и помечены как эвристика.
- **Библиотеку загружаем только для PDF.** pdf.js весит около 1,7 МБ; если бы она грузилась всегда, сайт открывался бы медленнее у всех, кто проверяет .docx.
- **Имена шрифтов читаем сами.** pdf.js их не отдаёт, но в PDF у каждого шрифта есть словарь с `/BaseFont /Имя`, а у встроенного — ссылка на файл шрифта `/FontFile`. Приставка `ABCDEF+` значит «встроено подмножество».
- **Шаблон проверяет сама программа.** Тест собирает шаблон для каждого набора требований и прогоняет его через проверку: если бы в шаблоне было неправильное поле, тест бы упал.
- **История хранится только в браузере** и без текста работы. Имя файла может содержать фамилию, поэтому её можно очистить.

## Вопросы для самопроверки

1. Почему по PDF нельзя найти пустые строки между абзацами, а по .docx можно?
2. Как программа узнаёт, встроен ли шрифт в PDF? Что значит приставка `ABCDEF+`?
3. Почему поле, измеренное по краю текста, может оказаться больше настоящего, но не меньше?
4. Как тест доказывает, что шаблон оформлен по требованиям?
5. Что хранится в истории попыток и почему там нет текста работы?
