# Этап 0: каркас проекта

## Что сделано

- **PLAN.md** — как я понял задачу, расхождения между документами, план этапов, риски, вопросы.
- **Инструменты.** Vite собирает сайт, TypeScript в строгом режиме ловит ошибки типов, ESLint ищет плохие места в коде, Prettier одинаково форматирует, Vitest запускает тесты. Одна команда `npm run check` запускает всё.
- **CI и деплой.** GitHub Actions на каждый пуш запускает `npm run check`, а из `main` публикует сайт на GitHub Pages.
- **Загрузчик профиля** (`src/core/profiles`): проверяет JSON-профиль и разворачивает ссылки `*From`.
- **Два теста-«сторожа»**: профиль школы валиден; эталон читается и не противоречит сам себе; тест по личному .docx пропускается, если файла нет.

## Почему так

- **CSP только в сборке.** Политика `connect-src 'none'` запрещает странице сетевые запросы, это и есть гарантия «файл не уходит». Но dev-сервер Vite сам общается с браузером по сети, поэтому в режиме разработки политика выключена.
- **ESLint запрещает `innerHTML`.** Если вставить текст документа как HTML, чужой файл может запустить скрипт (XSS). `textContent` вставляет только текст.
- **ESLint запрещает DOM в `src/core`.** Ядро должно работать и в браузере, и в Web Worker, и в Node (тесты). В воркере и в Node нет `document` и `DOMParser`.
- **Проверка профиля написана вручную**, без библиотеки: каждую проверку видно, и её можно объяснить. Ошибки собираются все сразу, а тексты ошибок живут в `src/i18n/ru.ts`, потому что ядро не пишет фраз для людей.
- **Ссылки `*From` разворачиваются при загрузке**, а не в каждом правиле. Так правила проще, и ошибка в ссылке видна сразу, а не когда правило сработает.
- **Тест эталона проверяет инварианты** (например, одиночные + в сериях = все пустые абзацы). Если в эталоне опечатка, мы узнаем об этом сейчас, а не когда будем гадать, кто прав: код или эталон.
- **Личный .docx в `.gitignore`.** В нём имена; в публичный репозиторий он не попадёт, а тест без него просто пропускается.
