# Доступность (WCAG 2.1 AA): что проверено

Цель из брифа (раздел 2.9): полная работа с клавиатуры, видимый фокус, aria-атрибуты, контраст, светлая и тёмная темы, уменьшенная анимация, ширина от 360 px.

## Автоматические проверки (e2e, каждый запуск CI)

| Что | Где проверяется |
|---|---|
| axe-core: нет нарушений уровня serious/critical на главной странице | `tests/e2e/app.spec.ts` |
| то же после проверки файла (отчёт, предпросмотр, панель исправления) | `app.spec.ts`, `stage2.spec.ts` |
| то же с открытым редактором требований | `stage2.spec.ts` |
| то же в режиме учителя с таблицей | `stage4.spec.ts` |
| то же в тёмной теме и с уменьшенной анимацией | `stage5.spec.ts` |
| клавиатура: Tab доходит до «Выбрать файл», Enter открывает выбор файла | `stage5.spec.ts` |
| то же в тёмной теме **с включёнными анимациями** (после появления отчёта) | `design.spec.ts` |
| клавиатура в отчёте: Tab до «Показать в тексте» → Enter переводит фокус на абзац; «Почему это важно» раскрывается по Enter | `design.spec.ts` |
| карта документа скрыта от экранного диктора (`aria-hidden`), щелчок по засечке переводит фокус на карточку | `design.spec.ts` |
| Lighthouse (мобильный): доступность 100 | вручную, docs/DESIGN.md |

Все проверки axe идут через `tests/e2e/axe.ts`: он сначала ждёт конца коротких анимаций (появление отчёта, оценка), потому что посреди движения axe может ошибиться с фоном под текстом. При падении в отчёте видно правило и элементы.

## Что сделано в интерфейсе

- **Клавиатура.** Все действия — обычные кнопки (`<button>`), ссылки и поля формы; скрытое поле выбора файла открывается кнопкой. После проверки фокус переходит на заголовок «Результат проверки», после «Показать в тексте» — на абзац в предпросмотре.
- **Видимый фокус.** Рамка 2 px цветом синих чернил (`--ink`) для всех элементов (`:focus-visible`); у карточки, к которой перешли, подсвечивается текст.
- **Объявления для экранного диктора.** Строка состояния — `role="status"` и `aria-live="polite"`; кнопки «Показать все места» и «Редактор требований» сообщают `aria-expanded`; столбцы таблицы учителя — `aria-sort`; значки ✓/✗ имеют `aria-label`; подсветка в предпросмотре дублируется скрытым текстом «ошибка:» / «замечание:».
- **Контраст.** Цвета заданы в `src/ui/tokens.css` для светлой и тёмной темы с контрастом текста не ниже 4,5 : 1 на бумаге и на столе; axe проверяет обе темы. Серьёзность никогда не передаётся только цветом: рядом слово «ошибка» / «замечание» / «совет».
- **Карта документа** — дополнительная навигация мышью; для экранного диктора и клавиатуры она скрыта, потому что те же места есть в карточках замечаний и в тексте работы.
- **Тёмная тема** — по `prefers-color-scheme`. **Уменьшенная анимация** — по `prefers-reduced-motion`: без сдвигов и плавной прокрутки, остаётся только смена прозрачности; линия проверки стоит на месте (`src/ui/motion.ts`).
- **Узкие экраны.** Одна колонка до 1100 px, таблица учителя прокручивается по горизонтали, длинные слова переносятся.

## Что проверить руками перед защитой

- Пройти весь сценарий только клавиатурой: выбор требований → файл → отчёт → «Показать в тексте» → редактор → исправление.
- Экранный диктор (NVDA в Windows или TalkBack на телефоне): объявляются ли «Проверяю…» и «Готово».
- Масштаб браузера 200 %: ничего не обрезается.
- Телефон шириной 360 px: отчёт читается, кнопки нажимаются.
