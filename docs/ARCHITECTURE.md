# Архитектура

## Поток данных

```
файл .docx (байты)
   │  страница: src/main.ts → postMessage (буфер передаётся, а не копируется)
   ▼
Web Worker: src/worker/check.worker.ts
   │
   ├─ reader/archive.ts   zip → XML-части; лимиты против zip-бомб; распознаёт .doc, PDF, ODT
   ├─ reader/document.ts  XML → модель: абзацы, прогоны текста, поля, таблицы, разделы
   │     └─ styles/resolve.ts  эффективное форматирование (docDefaults → стили → прямое)
   ├─ classify/index.ts   зоны (титульный лист, вводная часть, текст) и роли абзацев
   ├─ rules/*.ts          проверки; каждое правило — объект с check()
   └─ engine/index.ts     запускает правила по профилю, собирает отчёт
   │
   ▼  postMessage(отчёт)
страница: src/ui/report-view.ts → DOM (только textContent)
```

## Слои и ответственность

| Слой | Что делает | Что ему нельзя |
|---|---|---|
| `src/core/reader` | распаковка, разбор XML, модель документа | знать про правила и роли |
| `src/core/styles` | вычисляет настоящее значение свойства по цепочке стилей | — |
| `src/core/model` | только типы данных | — |
| `src/core/classify` | роли и зоны абзацев, таблица паспорта | проверять оформление |
| `src/core/rules` | проверки, по одному объекту на правило | менять модель, обращаться к DOM |
| `src/core/engine` | профиль → запуск правил → отчёт; ошибка правила не роняет проверку | — |
| `src/core/profiles` | схема профиля, проверка, разворот `*From`, встроенные профили | — |
| `src/worker` | запускает ядро в отдельном потоке | рисовать интерфейс |
| `src/ui` | экран, отчёт | разбирать .docx |
| `src/i18n` | все тексты: интерфейс (`ru.ts`) и правила (`rules-ru.ts`) | — |

Ядро (`src/core`) — чистые функции: никакого `window`, `document`, `DOMParser`. Это проверяет ESLint. Поэтому ядро одинаково работает в браузере, в Web Worker и в Node (тесты).

## Почему так

- **Web Worker.** Разбор большого файла занимает время. В отдельном потоке страница продолжает отвечать на клики; e2e-тест это измеряет.
- **Модель между XML и правилами.** Правило «красная строка» не знает, что отступ хранится в twips и может прийти из стиля. Оно видит готовое `firstLineIndentCm`. Так правила короткие, а ловушки формата собраны в одном месте.
- **Зона и роль — разные поля.** Пустой абзац на титульном листе одновременно «пустой» и «на титульном листе»; правила смотрят на оба.
- **Номер абзаца** — порядковый номер `w:p` в документе, включая ячейки таблиц, с 1. По нему отчёт показывает место, потому что номеров страниц в .docx нет.

## Что добавил этап 2

| Файл | Зачем |
|---|---|
| `src/core/engine/score.ts` | оценка 0–100 по формуле из `docs/SCORING.md` |
| `src/core/engine/passport.ts` | паспорт документа (слова, знаки, страницы по 1 800 знаков) и данные для предпросмотра |
| `src/core/profiles/share.ts`, `migrate.ts` | профиль в ссылке `#profile=…`; миграции версий схемы |
| `src/core/rules/headings.ts`, `structure.ts`, `page-numbers.ts`, `volume.ts` | правила HD-*, ST-*, PS-01, FN-01, NM-*, TH-01, VL-02, OUT-01 |
| `src/ui/profile-editor.ts` | редактор требований |
| `src/ui/preview.ts` | текст работы с подсветкой; рисуется порциями, чтобы не замораживать страницу |
| `src/ui/storage.ts`, `export.ts` | свои профили в `localStorage`; скачать JSON, скопировать список |

Отчёт (`Report`) теперь содержит группы замечаний (текст работы, содержание, титульный лист), паспорт документа и упрощённый текст абзацев для предпросмотра. Колонтитулы читаются как маленькие документы теми же функциями, что и основной текст.
