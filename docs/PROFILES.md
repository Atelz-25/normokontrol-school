# Профили правил

Профиль — это JSON-файл, который говорит, какие правила включены, насколько они строгие и с какими числами работают. Код правил чисел не знает: всё, что может отличаться в разных школах, лежит в профиле.

Код загрузчика: `src/core/profiles/` (`validate.ts` проверяет схему, `resolve.ts` разворачивает ссылки, `load.ts` делает и то, и другое).

## Схема, версия 1

```json
{
  "schemaVersion": 1,
  "id": "school-default",
  "title": "Типовой школьный проект",
  "description": "необязательно",
  "meta": { "...": "необязательно" },
  "structure": { "...": "необязательно" },
  "rules": {
    "PG-02": {
      "enabled": true,
      "severity": "error",
      "params": { "mode": "equals", "valueMm": 30, "toleranceMm": 1 },
      "confidence": "unconfirmed",
      "source": "S1",
      "note": "необязательно"
    }
  }
}
```

### Верхний уровень

| Поле | Обязательно | Что это |
|---|---|---|
| `schemaVersion` | да | версия схемы, сейчас только `1` |
| `id`, `title` | да | машинное имя и название для людей |
| `description` | нет | описание |
| `meta` | нет | справка для отчёта (см. ниже) |
| `structure` | нет | части документа и поля паспорта; на них ссылаются правила |
| `rules` | да | настройки правил по их ID (`PR-06`, `OUT-01` …) |

Любое другое поле на верхнем уровне или в правиле считается опечаткой и даёт ошибку.

### Правило

| Поле | Обязательно | Что это |
|---|---|---|
| `enabled` | да | включено ли |
| `severity` | да | `error` (ошибка), `warning` (замечание), `info` (совет) |
| `params` | да | параметры правила, свои у каждого |
| `confidence` | нет | `explicit` учитель сказала прямо · `inferred` выведено из её слов · `unconfirmed` требование есть, число не названо · `default` типовое значение |
| `source` | нет | откуда требование (`S1`, `S3,FILE` …) |
| `note` | нет | пояснение для человека |

Старые профили без `meta`, `structure`, `confidence`, `source`, `note` остаются валидными.

### `meta`

Свободный объект для справки. Проверяются только поля, которые использует отчёт:

- `teacherPriority` — порядок блока «Из-за чего в прошлый раз снижали баллы»;
- `boardPointsHypothesis` — чек-лист «Базовые пять пунктов»; элемент может объединять правила через `+`: `"FT-01+FT-02"`;
- `boardPoints` — то же, но подтверждённое; если оно есть, оно главнее гипотезы.

Каждое правило из этих списков должно быть в `rules`.

### `structure`

- `partsInOrder` — части документа по порядку: `id`, `title`, `aliases` (как часть может называться), `optional`, необязательное `sharesPageWithNext` (часть делит страницу со следующей, разрыв нужен только перед первой из пары). `id` не повторяются.
- `partNumberFormats` — допустимые форматы номеров частей.
- `passportFields`, `passportOptionalFields` — поля таблицы паспорта; необязательные должны быть среди обычных.

## Поля-ссылки `*From`

Чтобы не писать список названий частей в пяти правилах, правило может сослаться на `structure`. Загрузчик разворачивает ссылки **до** запуска правил, поэтому правило получает готовое значение и про `structure` не знает.

**Как разворачивается:**

1. Параметр, имя которого кончается на `From`, это ссылка. Результат кладётся в параметр без `From`:
   `aliasesFrom` → `aliases`, `partsFrom` → `parts`, `fieldsFrom` → `fields`, `optionalFieldsFrom` → `optionalFields`, `orderFrom` → `order`. Сам параметр `*From` после загрузки исчезает.
2. Значение — путь через точку, начинается со `structure`.
3. Если на пути встречается массив, следующий сегмент ищет элемент **по `id`**, а не по номеру: `structure.partsInOrder.toc` — часть с `id: "toc"`.
4. Если путь привёл к объекту, а у объекта есть поле с именем результата, берётся это поле. Пример: `aliasesFrom: "structure.partsInOrder.toc"` указывает на часть, и берутся её `aliases`.
5. Значение копируется: если правило его изменит, `structure` и другие правила не пострадают.

**Ошибки загрузки:**

- путь не начинается со `structure` или ведёт в никуда — `broken-ref`;
- параметр задан и напрямую, и через ссылку (`aliases` и `aliasesFrom` вместе) — `ref-conflict`;
- `partId` в параметрах (TH-*, CN-*) указывает на часть, которой нет в `partsInOrder` — `broken-ref`.

**Пример.** В профиле:

```json
"ST-02": { "enabled": true, "severity": "error", "params": { "aliasesFrom": "structure.partsInOrder.toc" } }
```

После загрузки правило ST-02 получит:

```json
"params": { "aliases": ["Содержание", "Оглавление"] }
```

## Встроенные профили

Появятся на этапе 1: «Типовой школьный проект», «Строгий (по мотивам ГОСТ 7.32-2017)», «Только ошибки» и «Наша школа» (`profiles/school-custom.json`). Новые школьные правила во встроенных профилях только советы или выключены.
