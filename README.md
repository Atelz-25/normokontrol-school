# Нормоконтроль

Веб-приложение, которое проверяет оформление школьного проекта (.docx) прямо в браузере: поля, шрифт, интервалы, красную строку, пустые абзацы, разрывы страниц, структуру. Для каждого замечания показывает, где оно в тексте, почему это важно и как исправить в Word.

> Статус: **этап 2**. Проверяются поля, шрифт, интервалы, отступы, пустые абзацы, разрывы страниц, заголовки, структура и содержание, паспорт проекта, номера страниц, объём теории и типографика: 51 правило, список в [docs/RULES.md](docs/RULES.md). Есть оценка 0–100, предпросмотр с подсветкой и редактор требований. План работ в [PLAN.md](PLAN.md).

## Приватность

Файл не покидает ваш компьютер. Приложение статическое, без сервера: разбор файла идёт в вашем браузере. В собранной версии стоит Content-Security-Policy `connect-src 'none'`, которая запрещает странице любые сетевые запросы. Проверить можно самому: откройте DevTools → Network, загрузите файл и убедитесь, что новых запросов нет.

## Быстрый старт

Нужен Node.js 22 или новее.

```bash
npm install
```

```bash
npm run dev
```

Перед коммитом этапа:

```bash
npm run check
```

Все команды описаны в [CLAUDE.md](CLAUDE.md).

## Структура

| Папка | Что там |
|---|---|
| `src/core` | ядро без DOM: чтение .docx, модель, стили, роли абзацев, правила, профили |
| `src/ui`, `src/report` | интерфейс и экспорт отчёта |
| `src/i18n/ru.ts` | все тексты интерфейса |
| `profiles/` | профили правил в JSON (`school-custom.json` — «Наша школа») |
| `fixtures/` | тестовые .docx; `fixtures/real/*.docx` личные и не попадают в git |
| `tests/` | тесты Vitest |
| `scripts/` | генерация фикстур и `docs/RULES.md` |
| `docs/` | бриф, школьные правила, документация, `learning/` для защиты |

## Ограничения

Файл .docx не хранит раскладку по страницам, поэтому номера страниц приложение не знает. Оно пишет «абзац №N» и только иногда «примерно стр. N». Подробный список будет в `docs/LIMITATIONS.md`.

## Зависимости

В собранный сайт попадают только две библиотеки:

| Пакет | Зачем |
|---|---|
| `fflate` | распаковка .docx (это zip); маленькая, работает в браузере, Web Worker и Node, создаёт буфер по размеру из оглавления архива — это защита от zip-бомб |
| `@xmldom/xmldom` | разбор XML: встроенного `DOMParser` нет в Web Worker и в Node, а ядро должно работать везде одинаково |

Остальные — только для разработки:

| Пакет | Зачем |
|---|---|
| `vite` | сборка и dev-сервер, требование брифа |
| `typescript` | строгая типизация, требование брифа |
| `@types/node` | типы Node для тестов и скриптов (чтение файлов фикстур) |
| `vitest`, `@vitest/coverage-v8` | тесты и покрытие, работают с той же конфигурацией, что и Vite |
| `eslint`, `@eslint/js`, `typescript-eslint`, `globals` | проверка кода, в том числе запрет `innerHTML` и DOM в ядре |
| `prettier`, `eslint-config-prettier` | единое форматирование; второй пакет выключает спорящие с Prettier правила ESLint |
| `@playwright/test` | e2e-тесты в настоящем браузере: загрузка файла, приватность (нет внешних запросов), файл 10 МБ |
| `@axe-core/playwright` | автоматическая проверка доступности страницы (WCAG) в e2e-тестах |
