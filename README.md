# Нормоконтроль

Веб-приложение, которое проверяет оформление школьного проекта (.docx) прямо в браузере: поля, шрифт, интервалы, красную строку, пустые абзацы, разрывы страниц, заголовки, структуру, список литературы, рисунки, таблицы и типографику. Для каждого замечания показывает, где оно в тексте, почему это важно и как исправить в Word.

**Сайт:** https://atelz-25.github.io/normokontrol-school/

> Статус: **все этапы 0–5 выполнены**. 91 правило (VL-01 ждёт нормы объёма от школы и пока выключено) — каталог в [docs/RULES.md](docs/RULES.md). План и решения — [PLAN.md](PLAN.md).

## Что умеет

- **Проверка** по профилю требований: «Наша школа» (по замечаниям учителя), «Типовой школьный проект», «Строгий», «Только ошибки» или свой.
- **Отчёт:** оценка 0–100 с формулой, «Из-за чего в прошлый раз снижали баллы», «Базовые пять пунктов», паспорт документа, карточки замечаний с местом в тексте («абзац №N», «примерно стр. N»), «почему это важно» и «как исправить в Word».
- **Текст работы с подсветкой** и кнопкой «Показать в тексте».
- **Сравнение версий:** загрузите исправленный файл — видно, что исправлено, что осталось, что появилось.
- **Автоисправление** безопасных правил: новый файл «…_исправлено.docx», исходный не меняется.
- **Редактор требований:** включить или выключить правило, поменять серьёзность и числа, «Темы проекта»; сохранить в файл, загрузить, поделиться ссылкой.
- **Режим учителя:** несколько работ сразу, сводная таблица, CSV.
- **Работает без интернета** после первого открытия; печать отчёта и сохранение в PDF.

## Приватность

Файл не покидает ваш компьютер. Приложение статическое, без сервера: разбор файла идёт в вашем браузере, в отдельном потоке (Web Worker). В собранной версии стоит Content-Security-Policy `connect-src 'none'`, которая запрещает странице любые сетевые запросы; автотест проверяет, что при проверке файла нет обращений к чужим адресам. Проверить можно и самому: DevTools → Network, загрузите файл — новых запросов нет. Офлайн-кэш хранит только файлы самого сайта.

## Быстрый старт

Нужен Node.js 22 или новее.

```bash
npm install
```

```bash
npm run dev
```

Перед коммитом:

```bash
npm run check
```

E2E-тесты в браузере (нужен `npx playwright install chromium`; если браузер не скачивается — `PW_CHANNEL=msedge`):

```bash
npm run test:e2e
```

Оценка качества на своих работах (протокол — [docs/EVALUATION.md](docs/EVALUATION.md)):

```bash
npm run evaluate -- <папка с .docx> <разметка.csv>
```

Все команды и соглашения — в [CLAUDE.md](CLAUDE.md).

## Структура

| Папка | Что там |
|---|---|
| `src/core` | ядро без DOM: чтение .docx, модель, стили, роли абзацев, правила, профили, движок, оценка, исправитель |
| `src/ui` | интерфейс: отчёт, предпросмотр, редактор требований, автоисправление, режим учителя |
| `src/worker` | проверка и исправление в отдельном потоке |
| `src/i18n` | все тексты: интерфейс (`ru.ts`) и правила (`rules-ru.ts`) |
| `profiles/` | профили в JSON (`school-custom.json` — «Наша школа»; `examples/` — примеры) |
| `fixtures/` | тестовые .docx: пары good/bad по каждому правилу, образцовая работа, разметка для оценки; `fixtures/real/*.docx` личные и не попадают в git |
| `tests/` | модульные тесты (Vitest) и e2e (Playwright) |
| `scripts/` | генерация фикстур и `docs/RULES.md`, оценка качества |
| `public/` | манифест, иконка и service worker для офлайн-режима |

## Ограничения

Файл .docx не хранит раскладку по страницам, поэтому номера страниц приложение не знает: оно пишет «абзац №N» и только иногда «примерно стр. N». Часть правил работает по признакам (эвристики) и может ошибаться — такие замечания помечены, и их можно отметить «здесь это есть». Полный список — [docs/LIMITATIONS.md](docs/LIMITATIONS.md).

## Зависимости

В собранный сайт попадают только две библиотеки:

| Пакет | Зачем |
|---|---|
| `fflate` | распаковка и сборка .docx (это zip); маленькая, работает в браузере, Web Worker и Node, создаёт буфер по размеру из оглавления архива — это защита от zip-бомб; ещё сжимает профиль для ссылки |
| `@xmldom/xmldom` | разбор и запись XML: встроенного `DOMParser` нет в Web Worker и в Node, а ядро должно работать везде одинаково |

Остальные — только для разработки:

| Пакет | Зачем |
|---|---|
| `vite` | сборка и dev-сервер, требование брифа |
| `typescript` | строгая типизация, требование брифа |
| `@types/node` | типы Node для тестов и скриптов (чтение файлов фикстур) |
| `vitest`, `@vitest/coverage-v8` | тесты и покрытие, работают с той же конфигурацией, что и Vite |
| `eslint`, `@eslint/js`, `typescript-eslint`, `globals` | проверка кода, в том числе запрет `innerHTML` и DOM в ядре |
| `prettier`, `eslint-config-prettier` | единое форматирование; второй пакет выключает спорящие с Prettier правила ESLint |
| `@playwright/test` | e2e-тесты в настоящем браузере: загрузка файла, приватность (нет внешних запросов), файл 10 МБ, офлайн |
| `@axe-core/playwright` | автоматическая проверка доступности страницы (WCAG) в e2e-тестах |

## Деплой

GitHub Actions на каждый пуш в `main` запускает проверки и e2e, собирает сайт и публикует его на GitHub Pages. В настройках репозитория один раз выбрано *Settings → Pages → Source: GitHub Actions*.
